# فرانچایز پلاس — بستهٔ اجرایی توسعه‌دهنده

**این سند چیست:** مرجع عملی توسعه‌دهنده برای اجرای Phase 2؛ از راه‌اندازی محلی و قواعد کد تا ترتیب تیکت‌ها و مرزهایی که نباید از آن‌ها عبور کرد.

**مخاطب:** توسعه‌دهندهٔ مجری یا Developer Agent که کد را می‌نویسد و دانش پیشین از این پروژه ندارد.

**دامنه:** فقط Phase 2 (زیرساخت، مخزن، دیتابیس، احراز هویت). صفحات و جریان‌های Phase 1 ساخته شده‌اند و در این سند فقط به‌عنوان وضعیت موجود توصیف می‌شوند.

**نسخه:** ۱٫۰ · **تاریخ:** ۴ آذر ۱۴۰۵ (۲۵ نوامبر ۲۰۲۶)

**مبنا:** Master Prompt مالک محصول و «خط مبنای فنی ۰٫۱» (۲۱ نوامبر ۲۰۲۶). در هر تعارض، تصمیم قفل‌شدهٔ مالک مقدم است.

**اسناد مرتبط:** `docs/TECHNICAL_ARCHITECTURE.md` (معماری، مرز ماژول‌ها، اهداف پشتیبان)، `docs/DATABASE_SCHEMA.md` (جداول و مهاجرت)، `docs/API_SPECIFICATION.md` (قرارداد API و خطا)، `docs/UI_UX_DESIGN_SYSTEM.md` (توکن‌ها و اجزا)، `docs/TESTING_AND_ACCEPTANCE.md` (ابزار و آستانهٔ تست). این سند نظم کار را تعیین می‌کند؛ جزئیات فنی از اسناد نام‌برده می‌آید.

## ۱. وضعیت تصمیم‌ها

هر حکم تجویزی در این سند با یکی از پنج برچسب زیر می‌آید: **(قطعی)**، **(خط مبنا)**، **(پیشنهاد)**، **(فرضیه)**، **(نیازمند تأیید)**. معنا و مصداق هر دسته:

| دسته | معنا در این سند | مصداق‌ها |
|---|---|---|
| تصمیم قطعی مالک | بدون اجازهٔ مالک تغییر نمی‌کند | بازار فقط ایران؛ فارسی و RTL؛ مدل Managed؛ انتشار برند فقط Admin/Super Admin؛ احراز هویت هر دو طرف؛ گفت‌وگو پس از تأیید؛ دسته‌بندی از دیتابیس؛ زرین‌پال با تأیید سمت سرور؛ چهار جریان درآمدی؛ هویت برند؛ بدون ویدئوی ساختگی |
| خط مبنای فنی | مبنای طراحی است، نه خرید سرویس یا انتخاب میزبان | Next.js + TypeScript؛ NestJS با REST نسخه‌دار؛ PostgreSQL + Prisma؛ Redis فقط در صورت نیاز؛ فایل خصوصی S3-compatible؛ نشست سمت سرور + OTP؛ REST + SSE/polling؛ تطبیق قاعده‌مند؛ پول به‌صورت integer؛ Docker |
| پیشنهاد | انتخاب پیش‌فرض این سند؛ با دلیل ثبت‌شده قابل تغییر است | Node 22 LTS؛ npm؛ ESLint و Prettier؛ چیدمان monorepo (با تأیید مالک)؛ Conventional Commits؛ GitHub Actions؛ Vitest و Playwright؛ رندر سمت سرور برای پنل‌ها |
| فرضیه | باور آزموده‌نشده؛ اگر رد شود، سند بازنگری می‌شود | یک توسعه‌دهندهٔ مجری؛ عمومی‌ماندن مخزن؛ ترافیک اولیهٔ کم؛ نرسیدن فونت Kalameh تا پایان Phase 2؛ دسترسی پایدار به GitHub از ایران |
| نیازمند تأیید مالک | تا تأیید، کار متوقف می‌ماند یا با فلگ خاموش اجرا می‌شود | تغییر چیدمان مخزن؛ انتخاب ارائه‌دهندهٔ CI؛ خرید میزبان یا فضای ذخیره‌سازی؛ قیمت، کمیسیون و استرداد؛ ارائه‌دهندهٔ پیامک؛ دادهٔ واقعی؛ انتشار عمومی؛ متن حقوقی؛ فونت و لوگوی نهایی؛ دامنه |

### ۱.۱ قفل‌هایی که مستقیماً روی کد اثر دارند

- **(قطعی)** هیچ دکمه، مسیر یا endpointی برای انتشار مستقیم برند یا فرصت توسط واگذارکننده ساخته نمی‌شود. واگذارکننده فقط «پیشنهاد» می‌فرستد و رکورد رسمی را Admin/Super Admin می‌سازد.
- **(قطعی)** گفت‌وگو پیش از تأیید تیم باز نمی‌شود؛ دسترسی کارشناس به گفت‌وگو محدود، زمان‌دار و ممیزی‌شده است.
- **(قطعی)** بازگشت کاربر از درگاه پرداخت اثبات پرداخت نیست؛ تأیید فقط با بررسی سمت سرور و ثبت idempotent انجام می‌شود.
- **(قطعی)** دسته‌بندی صنایع از دیتابیس خوانده می‌شود؛ افزودن دسته نباید تغییر کد بخواهد.
- **(قطعی)** تا تحویل ویدئوی واقعی، Hero فقط جایگاه رسانه دارد؛ ویدئو، تصویر یا افکت ساختگی اضافه نمی‌شود.
- **(قطعی)** در توسعه و تست فقط دادهٔ ساختگی؛ هیچ دادهٔ هویتی، مالی یا رمزی واقعی در مخزن عمومی قرار نمی‌گیرد.

## ۴. راه‌اندازی محلی

### گام ۱ — رفتن به پوشهٔ پروژه

```bash
cd franchise-plus-platform
```

**نتیجهٔ مورد انتظار:** `package.json` و `next.config.mjs` در همین مسیر دیده شوند.

### گام ۲ — نصب وابستگی‌ها

بار اول در مخزن تازه:

```bash
npm install
```

برای نصب قطعی و تکرارپذیر (و در CI) از فایل قفل استفاده کنید:

```bash
npm ci
```

هنگام افزودن وابستگی از `npm install <package>` استفاده کنید تا `package-lock.json` به‌روز شود.

**نتیجهٔ مورد انتظار:** پوشهٔ `node_modules` ساخته می‌شود و در صورت نبود تغییر وابستگی، `package-lock.json` دست‌نخورده می‌ماند.

### گام ۳ — اجرای محیط توسعه

```bash
npm run dev
```

**نتیجهٔ مورد انتظار:** پیام آماده‌شدن و آدرس `http://localhost:4173`. پورت ۴۱۷۳ در `package.json` ثابت است؛ آن را بدون دلیل تغییر ندهید.

| مسیر | چه چیزی باید دیده شود |
|---|---|
| `http://localhost:4173/` | نوار «پیش‌نمایش طراحی — Phase 1» و Hero خانه |
| `/opportunities/` | کارت‌های فرصت با برندهای ساختگی |
| `/opportunities/kafe-arka/` | جزئیات «کافه آرکا» و جدول مالی |
| `/how-it-works/` | مراحل کار و محرمانگی |
| `/join/` | انتخاب نقش گیرنده یا واگذارکننده |
| `/dashboard/` | پنل گیرنده با درصد تکمیل پرونده |
| `/panel/franchisor/` | پنل واگذارکننده، بدون دکمهٔ انتشار |
| `/panel/admin/` | صف بررسی و KPIهای مدیریتی |
| `/chat/` | گفت‌وگوی نمونه با پیام‌های ساختگی |

### گام ۴ — ساخت نسخهٔ استاتیک

```bash
npm run build
```

**نتیجهٔ مورد انتظار:** پوشهٔ `out/` با `index.html`، `404.html` و پوشهٔ هر مسیر ساخته می‌شود. این بیلد هیچ سروری اجرا نمی‌کند و در `next.config.mjs` هیچ متغیر پیکربندی جز `NEXT_PUBLIC_BASE_PATH` خوانده نمی‌شود.

### گام ۵ — پیش‌نمایش خروجی

```bash
npx serve out
```

**نتیجهٔ مورد انتظار:** صفحهٔ خانه روی پورت پیش‌فرض `serve` باز می‌شود و دارایی‌ها بدون خطای ۴۰۴ بارگذاری می‌شوند.

**(پیشنهاد)** با `output: 'export'` دستور `next start` برای سرو خروجی استفاده نمی‌شود؛ به‌جای آن سرور استاتیک به کار می‌رود. اسکریپت `start` فعلی در `package.json` با این معماری هم‌خوان نیست و در FP2-02 اصلاح یا حذف شود.

**هشدار مسیر پایه:** اگر بیلد با `NEXT_PUBLIC_BASE_PATH=/franchise-plus` گرفته شده باشد، دارایی‌ها زیر `/franchise-plus/_next/...` درخواست می‌شوند و سرو سادهٔ `out/` در ریشه، صفحهٔ سفید می‌دهد. برای پیش‌نمایش محلی، بدون این متغیر بیلد بگیرید؛ برای انتشار، با آن.

### گام ۶ — بررسی سلامت ظاهری

- در ۳۶۰، ۷۶۸ و ۱۲۸۰ پیکسل عرض، هیچ سرریز افقی یا متن بریده دیده نشود.
- کنسول مرورگر خطای قرمز نداشته باشد.
- در تب Network هیچ درخواست فونت یا اسکریپت به دامنهٔ بیرونی نباشد.

### خطاهای رایج

| نشانه | علت محتمل | کار درست |
|---|---|---|
| صفحهٔ سفید پس از انتشار | ناسازگاری `basePath` با مسیر سرو | بیلد با `/franchise-plus` و انتشار در همان مسیر |
| ۴۰۴ روی جزئیات فرصت تازه | نبود slug در `generateStaticParams` | افزودن رکورد به `lib/data.ts`؛ تابع از همان آرایه می‌سازد |
| خطای `next start` | خروجی استاتیک | استفاده از سرور استاتیک |
| پورت ۴۱۷۳ اشغال | پروسهٔ قبلی | بستن پروسهٔ قبلی؛ پورت پروژه تغییر نکند |
| فونت ناخواسته | جایگزین Vazirmatn | جایگزینی فقط پس از دریافت فایل و مجوز Kalameh |
| چیدمان معیوب RTL | استفاده از `left`/`right` | استفاده از ویژگی‌های منطقی |

## ۵. ساختار پوشه‌ها

```text
franchise-plus-platform/
├─ app/
│  ├─ layout.tsx                 ← lang="fa"، dir="rtl"، پوستهٔ سراسری
│  ├─ globals.css                ← توکن‌ها و کلاس‌های سیستم طراحی
│  ├─ page.tsx                   ← خانه
│  ├─ opportunities/page.tsx     ← فهرست فرصت‌ها
│  ├─ opportunities/[slug]/page.tsx
│  ├─ how-it-works/page.tsx
│  ├─ join/page.tsx
│  ├─ dashboard/page.tsx
│  ├─ panel/franchisor/page.tsx
│  ├─ panel/admin/page.tsx
│  └─ chat/page.tsx
├─ components/
│  ├─ shell.tsx                  ← نشان برند، سربرگ، پابرگ (کلاینت)
│  ├─ panel.tsx                  ← پوستهٔ مشترک پنل‌ها
│  └─ ui.tsx                     ← نشان وضعیت، کارت فرصت، اعلان، مسیر
├─ lib/
│  ├─ data.ts                    ← نوع‌ها و دادهٔ ساختگی
│  └─ fa.ts                      ← تبدیل ارقام فارسی
├─ next.config.mjs
├─ package.json
└─ tsconfig.json
```

**قاعدهٔ جای‌گذاری:**

| چه چیزی می‌سازی | کجا | الگو |
|---|---|---|
| صفحهٔ عمومی جدید | `app/<route>/page.tsx` | نام kebab-case، فقط `export default` |
| صفحهٔ پویا | `app/<route>/[param]/page.tsx` | همراه `generateStaticParams` |
| کامپوننت مشترک | `components/<name>.tsx` یا افزودن به `components/ui.tsx` | `export function` با نام PascalCase |
| پوستهٔ پنل | `components/panel.tsx` | استفاده از `PanelShell` |
| نوع و دادهٔ نمونه | `lib/data.ts` | `export type` و `export const` |
| تابع نمایشی خالص | `lib/fa.ts` یا فایل هم‌خانواده | بدون وابستگی به React |
| توکن و استایل پایه | `app/globals.css` | متغیر CSS |
| تست | `tests/` | در FP2-10 نهایی می‌شود |

**قواعد ساختاری:**

- صفحه‌ها داده را از `lib/` می‌گیرند و به کامپوننت‌ها با props می‌دهند؛ کامپوننت مشترک نباید مستقیم از `lib/data.ts` داده بخواند (استثنای فعلی: import نوع).
- منطق کسب‌وکار در فایل صفحه نمی‌نشیند. با ورود API، لایهٔ دسترسی در `lib/api/` ساخته می‌شود و صفحه فقط ترکیب می‌کند.
- هیچ صفحه‌ای از صفحهٔ دیگر import نمی‌کند؛ اشتراک از `components/` و `lib/` می‌آید.
- پوشهٔ `out/`، `.next/` و `node_modules/` ساختهٔ ابزارند و کامیت نمی‌شوند.

| دستور | کار | نکته |
|---|---|---|
| `npm ci` | نصب تمیز وابستگی‌ها | نیازمند `package-lock.json` |

| `npx tsc --noEmit` | بررسی نوع | پس از FP2-02: `npm run typecheck` |
